## 4. Guardrails and fail-forward rule

- **No evidence laundering:** `SOURCE-ONLY`, `OFFLINE PASS`, `LIVE HEADLESS PASS`, `PHYSICAL PASS`, `BLOCKED`, `FAIL` are distinct. Stage/response timings are not proof of a functional coding artifact.
- **Do not re-open closed work** unless the actual production path reveals a regression or an incompatible profile. Preserve existing GPT-OSS streaming, Tavily routing, native LangGraph task state, TTS reuse/Flush and cancellation.
- **No benchmark special-casing:** model budgets, endpoint routing, task verification, output-format fixes and artifact publication belong in shared production runtime/config, not five-command fixtures. Benchmark scripts may only inject, observe and report.
- **No silent provider access or deployment:** record each live request, respect existing quotas, don't Git-push or deploy externally without explicit user authorization, and do not fabricate links/paths or source citations. Open local files only within the task's allowed workspace.
- **When genuinely blocked:** first save all partial artifacts and the exact failure. A **new phase** is justified only if the blocker is independently reproducible or otherwise well evidenced, affects multiple next gates, and cannot be addressed as a small correction within the current phase. Name it `Phase N — <specific blocking dependency>` with a single exit condition; preserve the sequence and do not create new phases for routine bugs. If a gate can be partially closed, mark what passed and carry only the unresolved dependency forward.
- **Agent time and cost:** aim ~5–15 minutes per focused change/verification, sometimes longer for an intentionally bounded full acceptance campaign. No arbitrary 15-minute task-runtime limit on legitimate background coding jobs: distinguish **agent investigation time** from **Swift task execution time**. Prefer actual billed/consumed tokens over reserved estimates when usage is available. For a blocked run, provide a concise checkpoint rather than consuming 45–60 minutes auditing unrelated areas. Preserve live calls and token costs.
- **Documentation updates:** after each meaningful run update this file's **Current checkpoint** below and append at most one short ledger entry. Keep original evidence pointers rather than copying huge logs. Do not delete failures or rewrite historical results to show a PASS.
