## Executive decision

Retain the shared Session, Pipecat ingress, our two speech MCP servers, typed action adapters, receipt reconciliation, and the existing dashboard. They have useful software evidence and do not require wholesale replacement. Retain installed Onit as the scoped task harness: Groq-backed real project generation now succeeds repeatedly. Do not infer unrestricted agent capability from that bounded tool set.

ASR fidelity and acoustic interaction are the principal unresolved demo gates. Qwen2-Audio prefill improved controlled transcription, but saved silence still hallucinates, important command/entity errors exist, and live question-shaped requests have answer-shaped stored user text. The latest arithmetic evidence does not conclusively isolate the provider: original audio and raw provider response were not retained. Stop cycling generic prompt variations; compare the same retained input and exact request/response boundaries, then evaluate a transcription-specific backend through the existing MCP interface if needed.

University reasoning is intermittently useful for small/direct requests but repeatedly fails the actual Onit project workload. Groq GPT-OSS 120B LOW/streaming/2048 is the strongest demonstrated scoped-project candidate. It is an explicit experiment profile, not a changed default. GPT-OSS 20B remains a provisional conversational candidate, not a proven voice-latency winner. The final arithmetic turn failed because of our four-request experiment cap, not a Groq outage.

No evidence qualifies Pi deployment, acoustic response/stop latency, or reliable full-duplex echo handling. Do not buy new audio hardware solely from these reports; controlled intended-device evidence is still needed.

## Latest arithmetic boundary and corrections to prior conclusions

1. Browser microphone PCM and aggregate levels reached the bridge. No raw microphone or submitted-ASR audio was retained for this trial; frame counts cannot establish spoken words or clean segmentation.
2. Current Qwen adapter encodes mono16k PCM as WAV, uses explicit text instruction and assistant prefill, temperature0, nonstream,256-token cap. It extracts `choices[0].message.content`, checks finish_reason, reconstructs/removes the exact quoted wrapper and applies English validation. The latest run does not retain that raw HTTP response or an immutable effective-request fingerprint. Current code/configuration describes the intended path, not proof of every exact submitted byte.
3. Session `recognize_stream` publishes `result.text` as user text, then emits asr_final and returns it for reasoning. Archive stores two answer-shaped strings with role=user, delivery=asr_final. The payload-free trace stores IDs/timestamps, not the original text. The reasoning response is a separate assistant record. Dashboard renders by role with safe escaping.
4. Evidence therefore reaches the ASR-result/Session/archive boundary. It is consistent with the previously reproduced Qwen semantic-substitution failure, but cannot independently exclude wrong input segmentation, replayed/contaminated audio, request/configuration mismatch, or response extraction. There is no evidence of an assistant-to-user DOM role swap.
5. Correct earlier wording: “direct repeated evidence of ASR answering” was too conclusive for this latest trial. It is two answer-shaped stored user strings conditional on the user's intended questions. Controlled E18 synthetic failures do independently demonstrate the hosted route can answer instead of transcribe; they do not reconstruct this lost live audio.
6. The weather refusal completed with a browser sink acknowledgment before the fourth utterance. The reply to `but i miss it` was interrupted by the subsequent time question; earlier wording that the weather reply itself was interrupted was incorrect. Its interrupted assistant text is empty in the saved transcript, so its generated wording cannot be evaluated there. The fifth time question was recognized, then rejected locally before model transmission by the four-request experiment cap. Four successful preceding requests consumed it. It was not Groq429, university timeout, or a TTS failure. Weather refusal was truthful under this run's capabilities; it did not test configured weather retrieval.
7. Three browser ACKs mean playback source callbacks completed. Earlier user-confirmed audibility is limited to those reported trials. Neither ACKs nor stop dispatch prove sound onset/silence at the speaker. Latest endpoint→browser-send median1.359s/p95 3.261s, n=4; last-voiced→send median2.328s/p954.247s. These tiny descriptive samples include one interrupted turn and do not establish tail/SLA performance. No sums of unrelated medians or actual audible latency can be reported.
8. E21 fresh Session/worker per conversational case verifies only that harness's isolation. It does not fix E20's reused class connection. Browser bootstrap failure preceded inference; later response-header timeouts preceded generated code. Preview-loading race was a different post-generation checker defect and was retested successfully.

## Three next actions, proposed only

1. **Locate transcription divergence, then decide the ASR backend.** Question: does the same literal question become an answer in the raw provider response, or earlier/later? Smallest test: one opted-in speakers-silent session with one question and one command, retaining original/submitted audio hashes, bounded raw ASR outward response, effective settings and each text boundary under matching IDs. No whole-pipeline music trial. Acceptance: both literal question/command preserved at all downstream boundaries, one final/dispatch each; no answer substitution. Stop after the planned pair if divergence is reproduced. If raw response is wrong, ask owner for one official-reference comparison and prioritize dedicated-ASR evaluation; if audio differs, repair capture/segment ownership; if normalized/DOM text differs, repair extraction/binding. A passing pair is necessary but insufficient: use existing varied/held-out corpus next, with provider-specific audio consent and a bounded request budget.
